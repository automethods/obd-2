The shared-session and whole-application tests run the actual Python HTTP
server on an ephemeral loopback port. The command queue is exercised with
deferred requests and a controlled clock: at most one mutation is active.
Polling uses actual 250 ms simulated intervals; one-minute log capture does
not reduce controller sampling. Other tests generate fixtures from actual
VehicleSim, SensorBank, ScannerSession or the retained legacy Sim.

The application test loads the actual index and view scripts into a parsed
node harness with CPU Canvas. It covers startup, accepted/rejected gears,
driving, view/selection continuity, adapter connection, decoded replies,
legacy reference choices, DLC failure, recording, BEV READY and a model-only
inverter target. It does not emulate native browser layout or all DOM events.

DOWNLOAD VERIFICATION
The release is checked after it is built with:
python3 tests/check_download.py --downloads ../OBDII_Release_0_7
The checker uses the actual self-contained run.sh in an empty folder whose
path contains spaces. It verifies payload checksums, flat source layout,
new assets and guide, actual petrol/BEV driver/scanner/fault/export flows,
repeat startup, Python-only PATH, read-only download location, occupied
port and damaged-download errors, browser handoff, and SIGINT/SIGTERM
cleanup. The script records the observed results in its JSON report.
