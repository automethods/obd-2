WHAT THE NEW CHECKS ESTABLISH

- Service W/Up and S/Down inputs change the same physical model used by Drive.
  Repeated updates and service-tool navigation preserve held keys. Multiple
  keyboard/pointer sources release independently. Blur, hidden documents,
  Help and global setup release manual controls. Text entry and native UI
  arrows do not drive the car. Gear assistance and parking release use the
  existing command queue. WLTC owns input until explicit takeover.
- Odometer is the configured starting reading plus positive physical travel
  in either direction. Trip A has a separate baseline. Resetting Trip A does
  not advance time or reset vehicle state, total distance or prior history.
  The actual setup form, Cancel and explicit Apply behave consistently.
- Scan tool tabs retain real connection state, request/reply decoding and
  fault clearing. A numeric trend uses actual reply timestamps and preserves
  missing-value gaps. Raw details and the trace dock are opt-in. An explicit
  Expand trace control provides more inspection space when requested.
- Basic petrol -> PHEV -> basic petrol commits the chosen configuration.
  Configured unit labels replace inherited hybrid labels. Unfitted hybrid
  or combustion components are omitted from configured location views;
  disconnected fitted hardware remains present and fault-marked.
- Diesel defaults to the extended teaching set. Its 13-channel inventory,
  sampling periods and the four channels omitted in Basic were checked
  against the code. No Euro 4/5/6 compliance or fixed sensor-count rule is
  claimed; docs/DIESEL_SENSORS.html explains the scope and primary references.

PACKAGED DOWNLOAD ACCEPTANCE

The release process runs tests/check_download.py against the generated
standalone run.sh and its exact embedded ZIP before updating Google Drive.
That test checks checksums and extraction, startup in an otherwise empty
read-only folder with spaces, a Python-only executable search path, real
HTTP/diagnostic/fault/vehicle/WLTC requests, odometer/trip behavior, shipped
service/scanner assets, repeated launch, Ctrl+C/SIGTERM cleanup, corrupted
file rejection, and source-ZIP startup. The final external release record
stores the packaged result and Google Drive byte-for-byte readback hashes.

for the user's machine, not pre-filled results. The earlier PDF books remain
theory references with older UI screenshots.

DELIVERY

The OBD folder contains only run.sh and START_HERE.txt. Complete source,
models, guides and tests are embedded in run.sh. Runtime is Python 3.10+
standard library plus the browser; Vite, React, Node and Electron are not
runtime requirements. Export wanted logs before shutdown or replacing a run.
