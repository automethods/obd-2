One folder. Two files.

Your Drive download contains run.sh and START_HERE.txt. The launcher includes the simulator, sample vehicle, model bindings, books and editable source. Download the folder, extract its ZIP and open a terminal there.

python3 --version
bash run.sh

Use Python 3.10 or newer. No additional Python packages, Node.js, Rust or physical diagnostic adapter are required. Open http://127.0.0.1:8765 if your browser does not open automatically.

Begin with Live dashboard.

City drive is selected and paused. Press Run and use 1× speed for the smoothest demonstration. Keep the terminal open; press Ctrl+C there to stop. The temporary working files are removed, leaving the downloaded launcher ready for next time.

The simulator runs offline after downloading. External reference links need internet access. If port 8765 is occupied, use bash run.sh --port 8766 --no-browser, then open port 8766 in your browser.

How to read the lab

Choose a drive

City drive and Road cruise each run for 90 simulated seconds with a smooth virtual driver. Manual drive gives you the accelerator and brake. A selected route requests a speed; the plant, controls and faults determine what actually happens. Selecting a drive resets the session.

Read two kinds of values

The large cards and physical charts read the simulation state. The Live OBD session sends real requests to the local teaching ECU and decodes its replies. A diagnostic value is sampled and quantized; it can differ from physical truth during a sensor fault or remain as an explicitly old reading during a connection timeout.

Use one clock

Run / Pause and the step buttons control plant time. Capture pauses dashboard telemetry history, not the plant or server record. Diagnostic Replay explains the last request without sending it again. Camera controls remain usable while paused.

Explore the vehicle

The compact vehicle in Live dashboard and the full Virtual vehicle view use the same physical state. Exterior shows the original contoured body; Cutaway exposes the teaching components and wires. A lost wheel measurement does not stop the physical wheel.

Follow a fault

Open a connection, advance time, compare physical state and received data, read a warning, reconnect, then check again. Stored emissions warnings may need an explicit clear after repair. A battery-monitor shutdown can stay latched until an ignition cycle or a fresh run.

Keep the scope clear

The executable subset is OBD over CAN plus a small UDS service set in a generic Python teaching model. Only the engine ECU has diagnostic services; other modeled controllers expose state. No real ELM327, CAN adapter, OEM ECU firmware, MCD/ODX database import, external AI service or real vehicle connection is implemented.

A. START, NAVIGATE AND DRIVE

01

Check the downloaded folder

Download the OBDII Drive folder and extract its ZIP. The download should contain only run.sh and START_HERE.txt. Everything needed by the simulator is embedded in run.sh. No source ZIP or separate book download is required. Folder names containing spaces are supported.

Notes: ______________________________
02

Launch the complete standalone simulator

Run python3 --version, then bash run.sh in the extracted folder. Python 3.10 or newer is required. Open http://127.0.0.1:8765 if the browser does not open automatically. Expected: Workbench opens on Live dashboard, with City drive selected and the simulation paused. Keep the terminal open.

Notes: ______________________________
03

Navigate and change appearance

Use the left navigation: Live dashboard, Virtual vehicle, Training panel, Diagnostics and Object layers. Try Light / Dark at the top. Also locate Learning book and Instruments in the top bar. Expected: each view opens and the shared experiment is preserved. Choosing a drive/experiment or Reset starts a new run; top-level view changes may pause it.

Notes: ______________________________
04

Run and pause one shared clock

On Live dashboard press Run, watch the vehicle/readings/charts, then Pause. Expected: simulation time advances while running. When paused, physical readings and wheel rotation settle and hold; camera movement remains available. A diagnostic request reads the current state without advancing simulation time.

Notes: ______________________________
05

Step and adjust playback

While paused, press +0.1 s and +1 s. Try 1× speed and 5× speed while running. Expected: steps add exactly their stated simulated duration. Playback changes the relationship to wall time, not the plant equations. Return to 1× for the smoothest demonstration.

Notes: ______________________________
06

Watch the complete City drive

Select City drive to reset, then Run. The 90-second route begins rolling, cruises through town, brakes to a stop at the lights, pulls away onto a bypass, slows for a bend and stops again. Expected: driver phase/target/progress change together. Actual speed follows plant dynamics rather than being forced to the target. EV, hybrid and regenerative operation appear; the engine can legitimately show 0 rpm while the vehicle moves.

Notes: ______________________________
07

Compare Road cruise

Select Road cruise, then Run. Expected: the 90-second route starts near 55 km/h, accelerates toward 90 km/h, crosses a smooth hill, slows and settles near 80 km/h. Road grade, pedal demand, engine activity and power flow respond. Fuel used and distance accumulate. This is an original teaching route, not a measured or certification drive cycle.

Notes: ______________________________
08

Take over with Manual drive

Select Manual drive. Change Accelerator and Brake under Driver & response, then Run or step. Expected: the manual sliders are enabled, the physical vehicle responds, and no scripted route operates the pedals. Return to City drive or Road cruise to restore the virtual driver and begin a fresh run.

Notes: ______________________________

B. READ, CAPTURE AND COMPARE THE LIVE DATA

09

Understand the four large readings

Observe Vehicle speed, Engine speed, Coolant temperature and Engine load. These cards show physical/model state; the PID labels identify corresponding diagnostic questions. Expected: the coolant card stays at the physical temperature during a sensor fault, with a note about the invalid sensor. Do not mistake an engine-stopped EV phase for a missing rpm signal.

Notes: ______________________________
10

Expand charts and use the shared cursor

Run enough of a drive to collect data, then pause. Move the pointer across Vehicle & wheel speed, Engine RPM, Coolant temperature or Power flow. Try the expand icon on a chart and choose 15, 30, 60 or Full drive · 90 s in Chart window. Expected: the same cursor time is used across charts; values, units and legends remain readable when expanded or resized.

Notes: ______________________________
11

Pause dashboard capture separately

While a drive runs, press Capture, wait briefly, then press it again. Expected: the telemetry sample count pauses/resumes, while simulation time and current physical readings continue. Capture controls the dashboard telemetry history; live OBD requests and server-side run recording are separate. Save the exported run when you need the full server record.

Notes: ______________________________
12

Poll the teaching ECU while running

Keep Live dashboard visible and Poll OBD while running checked. Press Run. Expected: the live OBD session periodically asks for speed, rpm, coolant and load. Request/reply counts and CAN frame rows update. Untick polling: the physical plant continues while the last decoded replies retain their earlier sample times. Automatic polling pauses when the dashboard is hidden or the simulation is paused.

Notes: ______________________________
13

Request a sample while paused

Pause the simulation and press Scan now. Expected: four PID requests are made through the actual local diagnostic service, with bytes and decoded values. The simulation clock stays unchanged. These are generated in-memory ECU replies, not readings from an ELM327 or a real vehicle.

Notes: ______________________________
14

Inspect and filter the frame monitor

In CAN frame monitor choose All frames, 0x7DF requests and 0x7E8 replies. Expected: each row retains simulation time, direction, identifier and eight data bytes; changed bytes are highlighted. Clear display clears the visible monitor rows, not diagnostic fault memory or the simulation. Physical CAN arbitration and bit timing are not modeled.

Notes: ______________________________
15

Compare physical state with decoded OBD

Use Compare signal or a large reading card to select speed, rpm, coolant or load. Expected: Physical model and Last decoded OBD reply show separate values, the response bytes and decoding formula. Small differences can come from quantization or sampling. With a disconnected coolant sensor, the invalid -40°C report differs substantially from warm physical coolant; a timeout is not a zero measurement.

Notes: ______________________________

C. EXPLORE THE VEHICLE AND ITS MODEL

16

Use the vehicle inside Live dashboard

Drag the compact vehicle to orbit and scroll to zoom. Select a component or its part button, then use Inspect wiring. Expected: the selected component opens in Training panel with its properties. The compact vehicle reads the same simulation state as the gauges, charts and full vehicle view.

Notes: ______________________________
17

Switch exterior and cutaway views

Open Virtual vehicle. Try Exterior, Cutaway, the Body slider, Wires and Labels, then Top view, Side view and Reset view. Expected: the contoured body, cabin glass, wheels and internal teaching components remain usable. Record whether the renderer badge says WebGL2 or 2D fallback. The fallback is supported, with simpler rendering.

Notes: ______________________________
18

Distinguish physical wheel motion from sensor loss

Start a moving City drive or Manual drive. In the vehicle view select the front-left wheel, then open its sensor connection. Expected after stepping: physical wheel rotation continues while the reported measurement is unavailable. Pause holds motion. Moving wire dots indicate conceptual signal activity; they are not measured bus pulses or exact protocol timing.

Notes: ______________________________
19

Reload the bundled model and bindings — optional

In the full Virtual vehicle view expand Model & simulation bindings. Download Sample GLB ↓ and Bindings JSON ↓, then reopen them with Load GLB and Load bindings JSON. Try Restore sample. Expected: the sample loads with four physical wheel bindings. Imports last for the browser session. The built-in reader accepts rigid, uncompressed embedded triangle geometry and base colors; textures, external buffers, compression, skins, morph targets and animation clips are outside it. Three.js itself is not bundled; Model guide explains the separate adapter.

Notes: ______________________________
20

Check your browser layout and keyboard

Resize the window and try your normal desktop scaling in both themes. Use Tab to reach controls. Focus a vehicle canvas: arrow keys rotate, + / - zoom and Home resets. Expected: text, charts, the inspector and controls remain reachable. Record clipping, overlaps, a blank model or unresponsive input. GPU/WebGL output and full interactive browser behavior require these local checks.

D. OPEN CONNECTIONS AND FOLLOW THE CONSEQUENCES

21

Establish and open the coolant-sensor circuit

Open Training panel, select Coolant sensor and use 1 · Healthy baseline if needed. Expected: physical coolant is near the chosen 25°C start and sensing is valid. Press 2 · Disconnect, then +0.1 s. The ECU input rises toward 5 V and the sensor report becomes the invalid -40°C marker. Physical coolant remains warm; disconnecting alone does not advance detection timers.

Notes: ______________________________
22

Observe persistence, fallback and P0118

Press 3 · Advance 0.6 s, then 4 · Read diagnostic. Expected: the engine controller uses fallback and P0118 is stored. The ECU-side signal voltage remains observable even though the sensor branch is open. In Diagnostics, Stored engine warnings and Pending engine warnings show the corresponding emissions memory.

Notes: ______________________________
23

Repair first, then clear the remembered fault

Press 5 · Reconnect, then +0.1 s. Expected: valid sensing returns; the stored P0118 can remain. In Diagnostics > Live requests > OBD · emissions, choose Clear engine warning memory (04), then Stored engine warnings (03). Expected: reply 44 acknowledges clearing and repaired P0118 stays absent after further stepping. Clearing a still-open circuit is not a repair.

Notes: ______________________________
24

Isolate and restore the diagnostic CAN branch

Start a healthy drive and press Scan now. Open Diagnostic connector under Connections & health, then scan again. Expected: no new replies are delivered and the earlier decoded values are marked as last successful readings; the plant continues. Reconnect and scan to restore replies. Training panel shows that the independent supply/ground references remain 12.6 V and 0 V; they are not a solved auxiliary-battery circuit.

Notes: ______________________________
25

Watch a battery-monitor message go stale

Start a fresh City drive or choose Battery monitor in Training panel. Open the Battery monitor connection and Advance 0.6 s. Expected: receiver message age increases, power permission is removed and the supervisory/contactor state shows the protective response. A BMU CAN wire probe can still display increasing message age because the receiver monitors the silence.

Notes: ______________________________
26

Restore messages and reset a latched shutdown

Reconnect the Battery monitor and step +0.1 s. Expected: messages become fresh, but shutdown may remain latched. Start a fresh drive or Healthy baseline to recover. In the manual Battery monitor experiment you can instead turn Ignition / READY off, step +0.1 s, turn it on and step +1 s. Generic OBD 03 is not a reader for BMU-specific faults.

Notes: ______________________________
27

Drop and repair the front-left sensor

Choose Wheel-speed sensor in Training panel, or use a fresh moving drive. Open the front-left connection and Advance 0.6 s. Expected: measured FL speed is unavailable, physical wheel speed can remain nonzero and the controller reports degradation. Reconnect and step: measurement returns. A remembered module warning can remain. If the car has already stopped, restart before comparing motion.

Notes: ______________________________
28

Inspect individual objects, wires and scopes

In Training panel select a component, its socket and a wire. Inspect endpoints, connection state, unit, Simulation binding and Object properties · JSON. In Object layers select entries again. Expected: components, sockets/pins and wires remain distinct objects. A selected wire supplies the scope; a missing wheel sample is a gap, an open ECT input can still have a voltage, and BMU age remains observable. Gauge/length/reference properties are teaching metadata, not a solved whole-vehicle harness.

Notes: ______________________________

E. FOLLOW DIAGNOSTIC BYTES AND DEFINITIONS

29

Explore the connector front face

Open Diagnostics > Connector & layers. Select numbered contacts in the female vehicle DLC, then switch CAN, ISO 9141-2, KWP2000, J1850 PWM and J1850 VPW highlighting. Expected: CAN-H is pin 6, CAN-L 14, chassis ground 4, signal ground 5 and supply 16. Legacy pins 2/10/7/15 are reference roles. The drawing looks into the vehicle socket; the plug/rear wiring perspective is different.

Notes: ______________________________
30

Read the layer responsibilities

Select layers in the seven-layer teaching map beside the connector. Expected: DLC is physical access, CAN frames carry data, ISO-TP transports diagnostic application payloads, and OBD/UDS define requests and their meaning. Standards can span layers; the diagram does not claim seven separately implemented protocols. Representation/units are separate from raw bytes.

Notes: ______________________________
31

Ask the implemented OBD questions

In Diagnostics > Live requests > OBD · emissions, try Engine speed (01 0C), Vehicle speed (01 0D), Coolant temperature (01 05), Warning lamp & monitor (01 01) and Supported measurements (01 00). Expected positive replies begin 41 followed by the requested PID. Requests use 7DF or 7E0; replies use 7E8. Engine-stand road speed and EV engine speed can legitimately be zero.

Notes: ______________________________
32

Try UDS sessions and identification

Select UDS · ECU services. Read synthetic VIN (22 F1 90), Read lab part number (22 F1 87), Default diagnostic session (10 01), Extended diagnostic session (10 03) and Tester present (3E 00). Expected: requests use 7E0; replies begin 62 F1 90, 62 F1 87, 50 01, 50 03 and 7E 00 respectively. Identifiers are LAB00000000000001 and LAB-ECU-0001, both invented for this lab.

Notes: ______________________________
33

Replay one completed request slowly

After a request use Replay, Pause replay / Resume replay, Next step or the numbered Question / Connection / CAN frame / ECU service / Return path / Decode steps. Expected: the replay explains the saved request and its exact bytes. It does not transmit again, advance plant time or measure bus delay. Pause the simulation separately when you want the surrounding values to hold.

Notes: ______________________________
34

Inspect a multi-frame reply

Request Vehicle identity example (09 02) or the UDS VIN. In CAN / ISO-TP frame trace select Single Frame, First Frame, Flow Control and Consecutive Frame rows. Expected: the explanation separates transport control bytes, application data and padding, and shows the reconstructed identifier. The generated flow-control lesson is not a fully timed physical CAN sender.

Notes: ______________________________
35

Check expected negative/silent behavior — optional

In Enter diagnostic bytes use 7E0 with 22 00 00: expected 7F 22 31 for an unsupported data identifier. Use 7DF with 22 F1 90: this lab gives no application reply because its UDS subset requires 7E0. For session expiry, send 10 03 at 7E0, pause automatic polling, advance more than 5 simulated seconds without another diagnostic request, then inspect /api/state: diagnostic_session.hex returns to 01. Waiting while paused does not expire it.

Notes: ______________________________
36

Inspect the module/service definitions

Open Diagnostics > Protocol reference > Modules and their diagnostic access. Expand Inspect service definitions and download Definitions JSON ↓. Expected: four modeled modules and 19 existing request definitions. Only Engine ECU has diagnostic addresses/services. Battery monitor, hybrid supervisor and ABS/yaw controller are Simulation state only. Open Definition schema and extension guide: this is the independent obdii-lab JSON format, not an MCD/ODX importer or compatible mcd-diag-rs database.

Notes: ______________________________
37

Check runnable versus reference-only scope

Read the protocol cards. OBD over CAN and UDS over CAN are Runnable subset. ISO 9141-2, KWP2000, J1850 PWM/VPW, DoIP and LIN are Reference only. The signal-discovery note explains why changing bytes require a known mapping. No ELM327 AT-command emulator, physical adapter connection, OEM discovery, DBC reverse-engineering AI, security access, coding/adaptations or flashing is included.
