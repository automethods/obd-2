DOWNLOAD VERIFICATION METHOD
After building, the independent package checker is run with:
python3 tests/check_download.py --downloads ../OBDII_Release_0_8
The checker records its observed results in a separate JSON report. It
starts the actual self-contained run.sh alone in an empty folder with
spaces in its path. It checks payload hashes, flat source layout, bundled
assets, model/scanner/export flows, Setup/manual/WLTC/HVAC integration,
repeat startup, a Python-only PATH, read-only download location, occupied
port and damaged-download errors, browser handoff and signal cleanup.
This source record does not substitute for that packaged-download run.

SCOPE AND LOCAL ACCEPTANCE
The 26 user acceptance checks are in OBDII_START_HERE.txt and
docs/WORKSPACE.html. Python 3.10 or newer is required; the core simulator
needs no third-party Python packages. Development rendering and test
tools are not needed to use the download.

No native browser layout/event, GPU/WebGL output or particular Linux Mint
installation was verified. This is a generic teaching vehicle, not OEM
firmware or a validated complete chassis. HVAC is a lumped thermal/energy
model; it does not solve refrigerant flow or low-voltage battery energy.
ECU/sensor cavity assignments are illustrative; DLC standard pin roles
are distinguished from them. CAN traffic is message-level simulation,
not an electrical network solver. Individual CAN/power conductor faults
are not claimed. WLTC uses the official Class 3b speed target through an
automatic virtual driver; the result is not a certified WLTP test.

WLTC SOURCE
UN Regulation No. 154, Annex B1; Class 3b Tables A1/7, A1/9, A1/11,
A1/12, with checks against A1/13. Official publication:
https://www.legislation.gov.au/F2024L00446/asmade/2024-04-15/text/original/epub/OEBPS/document_1/document_1.html
The bundled data/wltc_class3b.json retains source and trace metadata.
