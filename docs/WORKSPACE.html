Continuous vehicle and synchronized modules · 0.9.6

Entering Drive or Diagnostics starts the vehicle clock automatically. Ignition, engine/READY and OBD connection remain independent. D and R require a running engine on an automatic petrol/diesel vehicle, or READY on a hybrid/electric vehicle, as well as the foot-brake and direction-change interlocks. Manual gearboxes retain their clutch rules.

Choose a module in the left sidebar or scan-tool dropdown: both select the same diagnostic target. Choosing a different module shows its own parameters without silently opening a connection. Connect names that module. Vehicle scan remains a separate discovery action.

ECU + Add parameter now includes fitted manifold absolute pressure (MAP), exhaust lambda, fuel rail pressure, boost, oil pressure, camshaft and knock signals, plus model fuel flow, integrated fuel used, torque and shaft power. Basic omits the extended-only sensors. Each card identifies OBD reply or Model sample; model channels are not claimed as executable OBD PIDs. The picker also offers the available sensor voltage and pulse measurements. Missing inputs remain unavailable rather than holding a valid-looking number.

MAP is absolute inlet pressure, not vacuum relative to a separately measured ambient pressure. Fuel trims, injector pulse width, injection timing and separate upstream/downstream lambda banks are not modeled. Basic/Extended describe teaching detail, not Euro certification. Euro 5/6 define emission and OBD requirements; actual fitted sensors depend on powertrain and emissions-system design. See the Euro 5/6 regulation and Bosch references for MAP and lambda.

Start WLTC is available from either workspace for an automatic vehicle. If moving, brake to a complete stop first; the task bar explains this condition. Start WLTC prepares ignition, engine/READY, transmission and pedals. Press a pedal or Drive manually to take over while the vehicle remains live. Gauges are always visible in service.

This package uses a Python standard-library server and plain browser JavaScript. Vite is a separate frontend development server with hot module updates and a production build tool. It is not required to run or edit this simulator; no npm installation is needed.

Connect and discover · 0.9.6

Connect to Engine ECU (or the named module) opens that unit’s live parameters and reads its own fault memory. The button identifies the target and changes to Connected to <unit> after connection. Reading that unit’s fault codes does not query other modules.

Vehicle scan is a separate discovery view. Choose the transport and Scan all control units to inspect the fitted units. No individual unit connection is required. Discovery leaves your current unit connection unchanged. Use Connect on a result to open that unit’s live data and faults.

Live values repeat automatically while connected. Refresh selects 0.25 s, 1 s or 1 min of simulation time. In Custom diagnostic request, Read starts repeated numeric parameter reads at the displayed interval. Identification and service commands execute individually, so clearing codes or changing a session cannot repeat unintentionally.

WLTC is a shared driving task, shown above both workspaces. Switching to Diagnostics keeps the cycle running. The vehicle clock keeps running.

Diagnostics & service — scan, units, wiring and configuration

Open the online lab

Open OBD II Lab in your browser and wait for the simulation engine to load. Choose a vehicle, apply its settings, then select Drive or Diagnostics & service. Python runs inside a browser worker; no installation or terminal is needed.

Ukraine defaults to Ukrainian; other countries default to English. Choose EN / Українська to save your own preference across AutoMethods.

The vehicle and its recordings belong to this browser tab. Export wanted data before reloading, resetting or changing the vehicle. Closing the tab ends that simulation.

Step 1: Vehicle · Step 2: Choose workspace

The app opens at step 1, Vehicle. Choose a base vehicle, then open Customize vehicle & test conditions to adjust transmission, driven wheels, mass, tires/road load, ABS/ESP, cabin equipment, driving task and environment. Your selections remain a draft until Continue. Continue creates the selected parked vehicle and opens step 2, Choose workspace. Nothing starts driving automatically.

At step 2 choose Drive for the cockpit, pedals, gears and WLTC controls, or Diagnostics & service for the scan tool, fault tests, vehicle units, signals, wiring and locations. The active application has these two workspace choices. You can switch between them without replacing the vehicle, resetting time, clearing faults or losing the recorded log. Held manual controls release when leaving Drive.

Inside Diagnostics & service, Diagnostics contains Scan tool and Guided faults. Vehicle units contains Unit map, Signals, Wiring & connectors and Locations. Vehicle configuration shows the fitted vehicle; Edit vehicle opens the same global configuration flow. There is one configuration for the whole session.

Use Change vehicle to edit a running session. It pauses the simulation and releases manual controls while you prepare a draft. Cancel returns to the previous workspace with the same vehicle, time, faults and log, and resumes the clock. Apply vehicle & return explicitly starts a new parked, ignition-off session, clears the previous run and faults, and disconnects the scan tool. Export wanted data before applying.

Back from Choose workspace returns to the vehicle choices. Continuing with an unchanged committed configuration keeps the same vehicle. If validation or application fails, the editor keeps your draft and displays the error; correct it before continuing.

Six base vehicles are available: Petrol basic, Petrol extended, Diesel, HEV, PHEV and BEV. Petrol/diesel can use a six-speed automatic or a six-speed manual with clutch. HEV/PHEV use the hybrid power-split model; BEV uses single-speed reduction. ESP requires ABS. Engine sensor detail and cylinder choices apply only to vehicles with an engine.

FWD, RWD or AWD changes the driven wheels. Mass, wheel rolling radius, drag area and rolling resistance affect motion and engine speed. Cabin heater/ventilation and A/C are separately configurable. ICE cabin heating uses coolant; the hybrid/electric presets use electric heating. Outside temperature initializes cabin and engine coolant temperature. These are declared generic model choices, not a complete catalog of production chassis or HVAC architectures.

Choose You drive for manual operation of the pedals, or WLTC Class 3b for the automatic virtual driver. A manual gearbox selects You drive because this version does not automate clutch/gear operation for WLTC. Dry, level road is the baseline; wet/snow/ice, slope and temperature are separate environment experiments.

First manual drive with an automatic gearbox

1. At step 1 choose Petrol basic. Under Customize vehicle & test conditions choose 6-speed automatic and You drive. Press Continue, then choose Drive at step 2. The new car has ignition OFF, selector P and the parking brake applied.

2. Switch ignition on. The powered dashboard and ECU become available, but the engine remains stopped. Press Start engine. Watch the short cranking state followed by idle RPM. The top VEHICLE LIVE label refers to simulation time; ENGINE RUNNING in the cluster refers to the engine.

3. Hold S or Down Arrow to press the foot brake, then click D. Alternatively click Brake + select D: it temporarily applies the virtual brake for that gear change and restores your current pedal inputs afterward. The same helper exists for R. It does not bypass the stopped/direction interlocks.

4. Release the parking brake. Hold W or Up Arrow for full accelerator pressure; hold S or Down Arrow for full foot-brake pressure. These keyboard inputs apply 100% while held and return to 0% when released. Hold an on-screen accelerator or brake pedal face for 35% pressure. The adjacent vertical 0–100% slider provides variable pressure; the live percentage and pedal depression show the same input. Releasing the pointer returns that pedal to zero. Brake is on the left and accelerator on the right; a manual vehicle adds the clutch at the far left.

5. N disconnects propulsion and the vehicle coasts. Stop before Park, Reverse or a direction change. Stop engine leaves the ignition on. HEV/PHEV and BEV use Enable READY; a hybrid can be READY with zero engine RPM, and a BEV has motor power instead of an engine tachometer.

Steer left with A or Left Arrow, and right with D or Right Arrow. Keyboard steering returns to center when released. C presses the clutch on a manual vehicle. The vehicle responds continuously while a workspace is open.

Driving keys work in Drive and Diagnostics & service, outside text entry and Help, while you have manual control. They release when you switch windows, hide the browser tab, change workspaces or enter vehicle setup. Multiple held keys are tracked independently: S can remain held while you click a gear selector; if W and Up Arrow are both held, releasing one leaves the other active.

Arrow keys keep their normal adjustment role when a slider is focused. Click the dashboard away from the slider before using arrow keys to drive. W/S and A/D provide the alternative driving controls.

Clock status and engine status are separate.

VEHICLE LIVE means time advances. Ignition powers the units. Start engine or Enable READY requests propulsion readiness.

Dashboard warnings and engine red zone

The dashboard uses a large red circled-P parking-brake indicator, plus red seat-belt and driver-door-open indicators. The lamps follow the same vehicle state as the controls and illuminate with ignition on. The new vehicle starts with the driver belted and the driver door closed.

If D or R is selected but speed remains zero with accelerator pressure applied, check the parking-brake indicator and the parking-brake message. Release parking brake explicitly before accelerating. Selecting a gear and pressing the accelerator do not release it automatically. The warning gives a direct release action; it changes the same parking brake as the transmission control.

Use the seat-belt and driver-door controls to unfasten/fasten the belt or open/close the driver door. The red warning clears when its cause is removed. These switches record BODY events only when their state changes; they do not create engine fault codes or add a propulsion interlock. They are warning demonstrations, not a complete occupant-restraint or door-mechanism model.

Engine tachometers show a red band beginning at the selected vehicle's configured redline. Petrol and diesel use their own limits; changing the vehicle changes the band. The BEV instrument shows motor power and has no combustion-engine RPM red band.

Keep the vehicle visible while diagnosing

A compact live dashboard stays above the tools throughout Diagnostics & service: Scan tool, Guided faults, Unit map, Signals, Wiring & connectors, Locations and the fitted Vehicle configuration summary. Pedals, ignition/engine/READY state and warning lamps stay visible. RPM/speed instruments, selected gear, coolant, fuel or traction charge, 12 V readings and distance counters remain visible. A BEV shows motor power instead of engine RPM.

Switch ignition on and start the engine or enable READY from this dashboard while the diagnostic tools stay open. Stop, Release parking brake, seat-belt and driver-door controls act on the same vehicle. The usual starter and vehicle-state interlocks still apply. The service dashboard also has momentary accelerator/brake pedals, a manual clutch when fitted, and assisted gear selection. W / Up Arrow, S / Down Arrow, A / D or Left / Right Arrow and C operate the same controls here. The full Drive workspace offers the larger instruments and cabin controls.

This display shares the existing session and clock. It does not start a second simulation or polling loop. The clock continues while you change service tools, independently of the OBD connection. Disconnecting a sensor or applying an intermittent fault changes the shared controller state, and the compact dashboard updates from that state. Sampled fault effects still follow the sensor/controller timing. Opening Edit vehicle enters the separate global configuration flow and pauses the session as before.

Odometer and Trip A

ODO and Trip A appear in both dashboards. Set an optional starting odometer under Vehicle → Customize → Cabin & equipment; the default is zero. Actual forward and reverse travel adds distance. Remaining parked or paused adds none.

Reset Trip A clears only the trip counter and does not alter ODO, engine state, time or existing recorded samples. It works during WLTC. A new vehicle or Reset starts again from the configured initial reading; mileage does not persist between launcher sessions. Complete JSON/CSV exports include the baseline, ODO and trip values.

Use the pedals while diagnosing

The service dashboard has physical momentary pedals and the same W / ↑ accelerator, S / ↓ brake, C clutch and A / D or ← / → steering controls as Drive. Press a pedal face for 35% pressure (clutch: 100%) or hold its vertical slider for 0–100%. Release returns pressure to zero.

Use Brake + select or Clutch + select for gear changes, and release the parking brake separately. Typing in fields, opening Help, entering setup or leaving the window releases or suppresses manual inputs. Service tool changes keep keyboard holds; changing between Drive and service releases them once. Pedal pressure changes the shared vehicle immediately on its next clock update.

During WLTC, the pedals show the virtual driver's input. Press a pedal or W/S to take manual control while the vehicle keeps updating. Release to release pressure. The explicit Take manual control action stops WLTC and leaves the vehicle clock live.

Manual gearbox and clutch

The manual configuration starts in N and has R plus gears 1–6; it has no P or D. Hold C for a fully pressed clutch, then press Start engine. Clutch + start engine performs the temporary clutch press for a stopped Neutral start.

To pull away, hold C and choose first gear, then release the parking brake. Hold the clutch slider near 100%; release C while keeping the slider held. Apply accelerator pressure and gradually drag the clutch toward 0%, then release the slider. W gives full accelerator pressure; the on-screen accelerator pedal face gives 35%, and its vertical slider provides finer control.

The selected gear determines the ratio; the manual model does not shift automatically. Clutch + select gear is a temporary shifting aid, not an automatic smooth launch. Abruptly releasing the clutch under load can stall the engine. Stop, select N, press the clutch and restart. Reverse/direction changes require a stopped vehicle; an unsafe downshift that would over-speed the engine is rejected.

Cabin heater and A/C

Cabin controls are in Drive. Turn climate on, choose a temperature and fan setting, and enable A/C when fitted. Cabin temperature responds gradually. A cold ICE engine initially has little useful cabin heat; output increases as the coolant warms. The electric heater can heat when the traction system is READY.

A/C and blower loads affect ICE shaft demand/fuel use. Electric heating/cooling and the blower draw traction energy on the hybrid/electric models. Diagnostics & service → Vehicle units → Cabin heater / A/C exposes temperatures and loads. Opening its module connector removes climate operation and measurements while physical cabin temperature remains. Missing cabin-temperature input leaves ventilation available but disables automatic heating/cooling.

WLTC: a repeatable target for the same vehicle

The vehicle configuration stage offers the official WLTC Class 3b speed target: 1,800 seconds, sampled at one-second intervals, with Low, Medium, High and Extra high phases. The peak target is 131.3 km/h. Its source is UN Regulation No. 154 Annex B1, reproduced in Australian ADR 111/00; source/version/checksum metadata is bundled with the trace.

Continuing to Choose workspace does not start the cycle. In Drive press Start WLTC. The virtual driver performs the start/READY sequence, selects Drive and uses the ordinary accelerator and brakes to follow the target. Actual speed is calculated by the vehicle model and recorded separately. Weak power, low grip, slopes or faults can cause a tracking difference.

The vehicle clock starts automatically in Drive or Diagnostics and controls the cycle, sensors, logs and scan-tool polling. Changing views or disconnecting OBD leaves the vehicle live. Press a pedal or choose Drive manually to stop WLTC and take control; gear selectors become available after takeover.

Use dry, level conditions for the baseline. Surface grip and road slope are not parts of the official speed trace. This is a generic training vehicle following an official target; it is not a certified WLTP emissions, fuel-consumption or range test. Completion holds the vehicle with the brake and leaves the powertrain on until you take over or stop it.

Official trace source: UN R154 Annex B1 in ADR 111/00 · bundled with source and checksum metadata.

Vehicle units, sensor purposes and wiring

Drive and Diagnostics & service share one vehicle, clock and log. Open Diagnostics & service → Vehicle units for the functional map; select a unit to inspect its inputs. Purpose groups distinguish starting/engine timing, running control, braking/stability, energy/temperature, cabin comfort, and information/monitoring. A separate sensor-group filter covers air, fuel, timing, cooling and other functional areas.

Importance labels describe implemented behavior. Crank input is needed for engine operation. MAF/MAP loss invokes a limited-torque fallback. Wheel/steering/yaw faults affect the fitted assistance. Fuel level is a derived information channel with no independent sender connector or modeled fuel-starvation fault. An input’s loss explanation states exactly what this simulator does.

Open full wiring schematic shows one central controller housing, with its connector banks inside and the fitted wired sensors around it. Whole unit and Focus connector keep the same controller identity. Follow component → connector → pin → wire to its endpoint and signal. Each supported sensor card shows Connected or Unplugged, the current controller-input value/validity, and a visible Disconnect/Reconnect button. The fault summary remains visible while you follow the connections.

The Engine response card is read-only: it shows actual combustion state, physical shaft RPM, mean shaft torque and fuel flow. Separate injector or ignition-actuator circuits and their pin faults are not modeled in this release.

Read pin role, protocol use, paired connection and signal example. The DLC drawing is the vehicle socket mating face, wide edge at the top, pins 1–8 above 9–16. CAN-H and CAN-L are pins 6 and 14, grounds are 4/5 and supply is 16. Its Open CAN branch/Reconnect CAN button affects tester communication. CAN is the communication layer; OBD/UDS are diagnostic services accessed through this socket.

Physical state and sampled measurements remain distinct. Tables show validity, sample period and age. An invalid/unavailable value is not a valid zero. Opening a connector changes the relevant measurements and model behavior; after repair a fresh sample may be needed. Stored fault memory is separate from the repair.

To try a visible fault, click Disconnect in the Crankshaft speed card. Its label changes to Unplugged. After sampling, the controller input becomes unavailable, combustion is inhibited and the teaching P0335 fault is reported according to its pending/stored state. The fault summary shows the connection, input validity, combustion/start state, physical shaft RPM and fault consequence together.

VEHICLE LIVE means that time is advancing; a disconnected sensor does not pause the simulation. The engine can be stopped or start-inhibited while physical shaft RPM coasts down and the moving vehicle continues to coast. Click Reconnect in the same sensor card and allow another sample to recover the input. Restarting the engine and clearing stored memory are separate actions.

For a fault overview, open Diagnostics & service → Diagnostics → Scan tool → Vehicle scan with ignition on, then choose Scan all control units. This is an explicit scan, not a background scan of every module. The engine result uses OBD replies; other units are labelled simulation-state inspection. Reconnect the sensor, allow a fresh sample, and restart the engine if it stopped. Clear retained fault memory separately when checking the repair.

The coolant divider has an electrical circuit model. Most additional sensor transfers, pulse previews and CAN waveforms are labelled teaching examples, not captured electrical traces. ECU/sensor connector assignments and 3D locations are illustrative. Locations links the same objects to the cutaway vehicle; it is not a driving-game world or OEM service-geometry model.

Sensor characteristics and timing groups

In Unit map, Group by offers Purpose, Sensor system, Signal type and Sample rate. In Wiring & connectors, Arrangement offers Functional group, Signal type and Sample rate around the same central controller. These choices reorganize the view; the original connector banks, pin identities and simulation timing remain the same.

Inputs are identified as analogue, digital on/off, pulse, discrete state or derived/calculated. Expand Characteristics for the declared measurement range, electrical transfer or pulse conversion, sampling period and limits. Calculated channels such as battery SOC and fuel level do not have an independent sensor connector. BMU covers the implemented pack-voltage, pack-current and pack-temperature sensors plus calculated SOC; individual cell wiring and balancing circuits are not implemented.

Sampling groups: 10 ms = 100 samples/s; 20 ms = 50 samples/s; 50 ms = 20 samples/s; 100 ms = 10 samples/s; 500 ms = 2 samples/s; 1,000 ms = 1 sample/s. The live pulse frequency is different: the selected 60-pulses/revolution crank model produces 850 Hz at 850 rpm, while its input is sampled every 20 ms. CAN bitrate is bits/second; it is not a sensor sampling rate or a message publication period. Recording and scan requests have their own intervals.

Live and intermittent sensor faults

Disconnect/Reconnect in a sensor map row or schematic card changes the running vehicle's connection. For an intermittent fault, select that sensor in Wiring & connectors and use Start intermittent. Connected seconds and Dropout seconds default to 3 and 1. Regular repeats these phases. Irregular varies the phase lengths reproducibly by about +/-25%, resolved to the 2 ms plant step. The countdown, dropout count, sample validity and consequences all follow the same simulation clock. The test advances automatically while a workspace is open.

Try a running petrol car's MAF input first: leave the engine idling, open the ECU wiring, select MAF, then start a regular test. During each open phase the measurement becomes invalid at its next sample and the controller uses its limited-torque fallback. A sufficiently long dropout produces pending and then stored P0102. The input and controller can recover in a connected phase while the stored code remains. Crankshaft loss inhibits engine operation instead; reconnecting and restarting are separate actions where a restart is needed.

Brief interruptions may be missed by the input sampling or end before the teaching diagnostic delay confirms a fault. This is expected. Every contact transition is recorded in Events with simulation time. A one-minute saved-log interval can miss short dropouts in graphs; use a shorter interval and export complete run JSON to retain the event history.

Stop & reconnect cancels the schedule and restores the connection. A direct Disconnect/Reconnect also cancels that sensor's schedule. Clearing diagnostic memory does not stop an active intermittent test; the fault may return. Sensors on BMU/ABS and other units use their declared simulation-state fault records rather than invented engine P-codes. These are generic intermittent-contact exercises, not a full vibration, corrosion or electrical-noise model.

The compact connection toolbar names the current vehicle and ECU. Use Live data for continuous selected-module values and graphs, Fault codes for that module’s fault memory, Vehicle scan for the fitted-unit overview, and Connector for pins and signal references. Raw request and response details are optional disclosures.

Messages and Events stay collapsed after read requests. Open their counter for a compact trace; Expand trace overlays the lower tools when more inspection space is needed. Collapse restores the tool area.

Connect, request, inspect and repair

For engine diagnostics use a petrol, diesel or hybrid vehicle. Open Diagnostics & service and switch ignition on in the compact live dashboard if the vehicle is off. This powers the units for communication without starting the engine. For a running-engine test, use Start engine or Enable READY in the same dashboard; the diagnostic tool stays open. Open Diagnostics → Scan tool, choose the matching 11-bit CAN bitrate (250 or 500 kbit/s) and Engine ECU, then Connect. The adapter is virtual. Changing the protocol/target requires applying the connection. The full Drive workspace remains available for pedals, steering and gear selection.

Live parameters update automatically. For an individual service, expand Custom diagnostic request, choose a named request/PID, then Read. Engine speed is service 0x01 and PID 0x0C: decimal 1 and 12. The request bytes are 01 0C. As a worked example, application reply 41 0C 0D 48 has data bytes A=0x0D=13 and B=0x48=72; (256×13+72)/4 gives 850 rpm. Message inspection distinguishes CAN address, transport framing, service and parameter/data bytes, with hexadecimal and decimal values.

The engine ECU runs the documented OBD services: current data 01, stored codes 03, clear 04, pending codes 07 and VIN request 09 02, plus the selected UDS session/identification/tester-present examples. The supported service list identifies individual PIDs and units. A health scan records actual engine OBD responses; other modules are explicitly labelled simulation-state inspection without invented OEM addresses. BEV has no combustion-engine OBD endpoint.

Wrong bitrate, ignition off, an unplugged tester CAN branch or an open unit connector produces an explicit unavailable/no-reply reason. K-line, J1850, 29-bit CAN and DoIP entries are references in this release. Choosing a reference does not run that transport.

For an end-to-end fault: connect the engine scan tool, open Guided faults → Coolant sensor circuit, disconnect and sample 0.6 seconds. Inspect the high input, invalid measurement, fallback and P0118. Reconnect and sample; confirm the measured value returns. Clear retained emissions memory separately, then read again. The freeze-frame pane is model confirmation memory, not a complete implementation of OBD Mode 02.

Clock, recording and exports

The vehicle clock starts automatically when you enter Drive or Diagnostics. Ignition, engine/READY and the OBD connection are separate controls. Use Time scale to change the model clock rate. Keys 1 and 2 switch Drive and Diagnostics; driving controls are suppressed while typing or in Help. Change vehicle pauses the editor; apply or cancel resumes the workspace.

Log every 0.1 s, 1 s or 1 min selects saved-sample spacing in simulation time. It does not change sensor/controller sampling periods. Scan-tool continuous reads have their own 0.25 s/1 s/1 min request interval. Both follow the continuously updating vehicle clock.

Export → Recorded signals as CSV preserves values, units and validity with configuration and gear. JSON exports contain state and traces; the workspace report also keeps recorded samples and view/selection. Export before Apply vehicle & return, Reset or shutdown. Frontend history is bounded to 9,000 samples, interval recording to 20,000 samples, and diagnostic rows to 1,000; export periodically for long experiments.

Scope and verification

This is an online browser application. The original Python simulation engine runs in a browser worker through WebAssembly; no application installation is needed. Teaching models simplify engine/gearbox behavior, longitudinal tire forces, yaw assistance, hybrid power flow and cabin heat transfer. Manual clutch, HVAC and chassis settings are functional, but detailed suspension, clutch temperature, refrigerant dynamics, full body electronics, airbag deployment and external charging are not simulated.

CAN/ISO-TP frames are generated diagnostic transcripts. Physical arbitration, bit stuffing, propagation and electrical bus errors are not simulated. There is no real-adapter connection, OEM flash/coding/security access, MCD/ODX importer, CARLA integration or CAN reverse-engineering pipeline in this download.

Automated verification uses model tests, real loopback API checks, parsed-node UI interactions and CPU Canvas/SVG checks where applicable. Those methods do not establish native browser event/layout, WebGL GPU or Linux Mint compatibility on your particular machine. Use the browser checks below. The included older PDF books remain theory references with earlier UI screenshots; this guide describes version 0.9.10.
