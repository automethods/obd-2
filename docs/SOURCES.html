Sources and evidence boundaries

Version 0.3.0 · Research date: 9 November 2026. The documentation paraphrases the sources; original documents remain in their existing locations. The simulator source code and tests are the authority for implemented behavior, not the source list below.

Public primary sources

S1 California Air Resources Board, On-Board Diagnostic II Systems Fact Sheet, 19 September 2019 OBD-II monitors emissions-related components and stores malfunction information. The document’s regulatory dates are jurisdiction-specific and are not used as a global applicability claim.
S2 Linux kernel documentation, ISO 15765-2 / ISO-TP Physical versus functional addressing, single/multi-frame transport, flow control, sequence handling and the Linux socket interface. It does not provide a Toyota message database.
S3 Toyota Motor Corporation, Toyota Develops New Hybrid System, 17 April 2003 Manufacturer overview of THS-II power splitting, propulsion modes and regenerative braking. Describes that historical system, not every later Toyota hybrid.
S4 Modelica Association, Functional Mock-up Interface specification 3.0.2, 27 November 2024 FMU packaging, Model Exchange, Co-Simulation, Scheduled Execution and clocks. FMI export is a proposed extension, not a delivered capability.

S6 QEMU project, Arm System emulator A matching CPU architecture alone is insufficient; firmware depends on a supported board/machine and its devices. No assertion is made that QEMU supports an unidentified Toyota ECU.
S7 Renode project, Peripheral modeling guide Register/peripheral models and the relationship between CPU accesses, memory and the simulated system bus. No Renode peripheral implementation is included in this release.
S8 MathWorks, What Is Hardware-in-the-Loop? and SIL, PIL and HIL tests Terminology for model, compiled software, target processor and controller-hardware testing; equivalence testing. MathWorks products are not required by this lab.

S10 Linux-CAN, can-utils repository, candump source, isotpsend source Capture/replay and ISO-TP utilities for a later Linux virtual-CAN workflow. Those two source headers specify GPL-2.0-only OR BSD-3-Clause; inspect individual files rather than assuming a uniform repository license.
S11 Ircama, ELM327-emulator repository, license Adapter/scan-client emulation and an optional Toyota Auris Hybrid request dictionary. It is not a Prius firmware/physical model. The repository identifies CC BY-NC-SA 4.0.
S12 Texas Instruments, Monitoring NTC Thermistor Circuit With Single-Ended ADC, SBAA338A, revised June 2022 NTC divider topology, beta resistance/temperature relationship and ratiometric ADC principle. The lab’s 5 V, 2,200 Ω, 2,500 Ω, 3,500 K and timing choices are synthetic; this source does not establish a Toyota sensor calibration or pin assignment. ADC settling and tolerances in the application note are not implemented here.
S13 Elm Electronics, ELM327 data sheet, version 2.3 Printed p82, Figure 8: vehicle J1962 connector numbering and orientation. Printed p84, Figure 9: adapter reference circuit and protocol pin roles. Supports the DLC reference, not execution of an ELM adapter or analog CAN waveforms.
S14 ScanTool.net / OBD Solutions, Which OBD-II protocol is supported by my vehicle? Vehicle-connector diagrams, ground/supply functions and protocol-dependent pin assignments. The CAN lesson uses pins 6/14; legacy pins are reference-only. Historical market/date statements are not used as current global applicability guidance.

Evidence labels used in this package

Manufacturer fact means a scoped statement supported by a Toyota source, such as a historical gear connection or nominal battery voltage. Standard/protocol reference means a diagnostic or interoperability concept supported by its identified specification or official implementation documentation. Teaching assumption means a parameter, threshold, signal, control law or scenario chosen for learning. Verified implementation result means behavior observed by running this package; it does not imply measured vehicle fidelity.

All generic hybrid parameters, control periods, fault debounces, synthetic network signals, torque policies and simplified tire/thermal behavior belong to the teaching-assumption category unless an individual item says otherwise. No Toyota CAN identifier, proprietary PID, DTC subcode, firmware compatibility or production protection threshold is inferred from a plausible-looking number.

The new connector reference applies the same boundary to schematics: the DLC’s referenced positions and roles are distinct from fictional J-ECT and X1 lesson assignments. X1.1 is an internal reference test point, not a claimed physical ECU cavity. No real Toyota connector part number or harness layout is inferred. The 5 V ECT circuit and ideal 12-bit conversion are executable teaching models; their computed values are not recorded vehicle measurements. The workspace guide explains how invalid, substituted and stale values remain visible with their validity context.

For a later vehicle-specific model, maintain a provenance record per parameter: symbol, unit, value or map, vehicle generation, source page or dataset, measurement conditions, uncertainty, software revision and license. A publicly visible file can still have redistribution restrictions. Reference source locations and preserve notices when including third-party firmware or model code.
