Vehicle configuration · Diesel sensor reference

Diesel has an extended sensor set.

Choose Diesel · common-rail in vehicle setup. Its default engine detail is Extended sensors: 13 channels belong to the engine ECU. Each channel below has its own update period and a declared consequence when disconnected.

What this configuration represents

This is a generic common-rail turbo-diesel teaching vehicle. It is not a certified Euro 4, Euro 5 or Euro 6 engine, an OEM wiring diagram, or an emissions measurement. Choosing a sensor detail level changes the simulated inventory; it does not select an emissions certification.

The 13-channel count is for the engine ECU. Accelerator position belongs to the vehicle controller; transmission, brake/stability, body, instruments and cabin climate have their own channels. The fuel-level display is a calculated tank/consumption value with no independent level-sender connector in this model. Selecting more cylinders does not create additional lambda banks or extra exhaust probes.

What Basic and Extended actually change

Extended is the diesel default. It includes all 13 ECU channels above. Basic has 9 ECU channels: it omits camshaft speed, fuel rail pressure, boost pressure and oil pressure. The four omitted channels are marked “Extended only” in the table.

The current diesel filter keeps the NOx and DPF pressure teaching channels in both detail levels. This makes Basic a smaller teaching inventory, not a historical Euro 4 vehicle. Petrol knock sensing is not fitted to the diesel configuration. ABS, ESP, transmission and cabin equipment remain separately configurable.

Use the intended distinction

Choose Basic to inspect fewer inputs. Choose Extended to inspect the additional engine-control channels. A production engine’s equipment list requires a specific engine and aftertreatment architecture; the detail selector does not supply that information.

Signal type, sampling and logging are different

Analogue in this table means the lab’s electrical representation. Coolant uses a solved thermistor circuit with a nominal 5 V reference. Other analogue channels map their declared range to an illustrative 0.5–4.5 V display. That mapping does not identify the real interface of a production lambda, NOx, pressure or temperature sensor.

Pulse frequency is not sampling frequency. The crank example uses 60 pulses per revolution, so its displayed pulse frequency in hertz equals the rpm value numerically. The cam example uses one pulse per cam revolution; at 1,200 engine rpm, the cam turns at 600 rpm and its example signal is 10 Hz. Both channels are sampled every 20 ms, or 50 times per simulated second. Individual edges, missing-tooth decoding and sensor voltage waveforms are not simulated.

Logging selects observations to save. Selecting one log entry per minute does not make a sensor or the ECU run once per minute. The plant advances every 2 ms; ECU tasks and the sensor scheduler run on the existing 10 ms schedule; individual channels retain the update periods shown above. Pausing the simulation also pauses sampling. CAN bitrate describes bits per second on the network and is separate from all of these rates.

Unplug a sensor and follow the consequence

  1. Configure the diesel, switch on ignition and start the engine. Open its engine ECU in Diagnostics & service and choose a sensor connector.
  2. Disconnect the connector, or select a timed intermittent disconnection. Run the simulation so the owning channel can take its next sample.
  3. Compare the physical value, sampled value/validity, engine response and fault memory. An open wire removes a measurement; it does not remove the physical temperature, shaft or pressure being represented.
  4. Reconnect and allow another sample. The present input can recover while stored fault memory remains available for diagnosis. Repair and clearing stored codes are separate actions.

The generic sensor-bank faults use accelerated teaching persistence: a pending code after 0.2 s of missing sampled input and a stored code after 0.5 s. Detection first waits for that channel’s sampling period, so the 1 Hz NOx channel reacts later than the 50 Hz crank channel. The coolant channel follows its existing NTC/ECU fault path. These are simulator schedules, not regulatory monitor enable conditions or OEM diagnostic calibrations.

An intermittent opening shorter than a channel’s sampling period can occur between samples and leave no recorded fault. A longer interruption can produce a missing sample, fallback or a stored code depending on its duration. Crank loss inhibits the engine; a missing exhaust-monitoring input can leave the engine running. “Still running” therefore does not by itself mean that disconnection failed.

Euro 4–6 does not give one universal sensor count

An emissions stage alone is insufficient to identify a vehicle’s lambda-sensor count. Engine design, exhaust layout and monitoring strategy also matter. The Euro 5/6 approval documentation in Regulation (EU) 2017/1151 asks manufacturers to identify oxygen/lambda, NOx and particulate sensors, their types and locations, and their OBD monitoring arrangements. It does not serve as one fixed sensor inventory for every vehicle. [1]

For a concrete manufacturer example, Bosch’s double-injection SCR layout labels three NOx sensors, one lambda sensor, one particulate-matter sensor and one differential-pressure sensor, alongside two dosing modules. This is one documented system architecture, not a mandatory count for every Euro 6 diesel. [2]

A fuller Euro-era teaching variant would need an explicit engine and aftertreatment layout, the corresponding sensors and actuators, thermal/chemical behavior, and monitor logic. This release does not implement those variants or make a Euro-compliance claim. Use the real vehicle’s engine code, repair documentation and wiring diagrams to determine its actual probe count and connector assignments.
